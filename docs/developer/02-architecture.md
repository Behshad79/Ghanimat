# ۰۲ · معماری

## مسیریابی

- `src/main.tsx`: پیش‌فرض `HashRouter` (برای میزبانی ایستا روی GitHub Pages). با `VITE_ROUTER=memory` از `MemoryRouter` استفاده می‌شود (نسخهٔ جاسازی‌شده در artifact).
- `src/App.tsx`: کاربر واردنشده به `/login` می‌رود. چهرهٔ نقش (`full`/`simple`/`partner`) تعیین می‌کند `/admin`، `/simple` یا `/partner` باز شود. هر مسیر ناشناخته داخل `/admin` صفحهٔ ۴۰۴ (`NotFound`) را نشان می‌دهد.
- **پارامترهای کوئری قراردادی** (در تولید حفظ شوند، چون لینک‌های داخلی پنل به آن‌ها وابسته‌اند):

| پارامتر | معنا |
|---|---|
| `tab` | زبانهٔ فعال صفحه |
| `st` | فیلتر از پیش تعیین‌شده روی جدول (چند مقدار با `|`) |
| `fl` | برچسب فیلتر برای نوار «از کارت … آمده‌اید» |
| `tb` | نام جدول هدف وقتی صفحه چند جدول دارد |
| `p` | بازهٔ زمانی (`today`، `7d`، `30d`) |
| `q` | جست‌وجو یا برچسب میلهٔ نمودار در صفحهٔ جزئیات شاخص |
| `from`، `v`، `to` | مبدأ، مقدار و مقصد کارت شاخص برای `/admin/insight/:key` |
| `view` | نمای خاص (مثلاً `archive` در چاپ) |
| `step` | مرحلهٔ ویزارد کالا |

## لایهٔ داده (`src/shared/lib/store.ts`)

| تابع | نقش در پروتوتایپ | معادل در تولید |
|---|---|---|
| `useDB()` | خواندن واکنشی کل داده | هوک‌های داده (مثلاً TanStack Query) روی endpointهای GET |
| `getDB()` | خواندن غیرواکنشی | — |
| `mutate(fn, log)` | تغییر داده + ردیف لاگ ممیزی | فراخوانی endpoint عملیات؛ لاگ ممیزی سمت سرور |
| `snapshot()` | بازگردانی برای «واگرد» | endpoint بازگردانی یا اعمال معکوس |
| `fakeCall()` | شبیه‌سازی تأخیر و خطای سرویس بیرونی | فراخوانی واقعی API |
| `sendSms()`، `notify()` | ثبت پیامک و اعلان | صف پیام سمت سرور |
| `takeCode()` | تولید کد کالا و واحد | شمارندهٔ اتمی سمت سرور |
| `can(module)`، `permOf(action)` | دسترسی ماژول و مجوز عملیات | همین منطق، اما **اجباری سمت سرور** |

قاعدهٔ مهاجرت: همهٔ جاهایی که `mutate(` صدا زده شده یک عملیات سمت سرور است. فهرست کامل با فایل و خط در [06-api-contract.md](06-api-contract.md).

## نشست (Session)

`useSession()` نقش فعال، تم، حالت صفحه (`view`)، شبیه‌سازی سرویس (`simulate`)، «مشاهده به‌جای» (`viewAs`)، منوهای جمع‌شده و سنجاق‌ها را نگه می‌دارد. در تولید: نقش و کاربر از توکن، بقیه ترجیحات کاربر سمت سرور.

## نقش و دسترسی

- تعریف پایه: `src/shared/data/roles.ts`. در پایگاه‌داده کپی و از «تیم و دسترسی» ویرایش می‌شود.
- دسترسی فردی بر نقش مقدم است. مدیر کل همیشه همه‌چیز را دارد و خانه‌های جدولش قفل است.
- «مشاهده به‌جای…» فقط برای مدیر کل؛ رابط را با دسترسی نقش دیگر نشان می‌دهد.
- عملیات حساس (`perms`): `allow` اجرا می‌شود، `approve` درخواست تأیید می‌سازد، `deny` دکمه را غیرفعال با توضیح نشان می‌دهد.

## تم، جهت و قلم

- `data-theme="light|dark"` روی `html`؛ همهٔ رنگ‌ها متغیر CSS. هیچ رنگ ثابتی داخل کامپوننت نیست مگر رنگ داده (نمودار، لوگو).
- RTL کامل با کلاس‌های منطقی Tailwind. اعداد فارسی با `fa()`؛ ورودی‌ها اعداد لاتین را هم می‌پذیرند.
- قلم Peyda نسخهٔ بدون لاتین؛ متن لاتین (سریال، کد) با Vazirmatn.

## حالت‌های صفحه

کامپوننت `Page` در `src/shared/ui/page.tsx` حالت‌های `empty`، `loading`، `error`، `noaccess`، `offline` را برای همهٔ صفحه‌ها یکسان پیاده می‌کند. در تولید همین کامپوننت به وضعیت درخواست داده وصل شود.

## نسخه‌های ساخت

| فرمان | خروجی |
|---|---|
| `npm run build` | نسخهٔ ایستا با HashRouter در `dist` (GitHub Pages) |
| `VITE_ROUTER=memory npx vite build` | نسخهٔ قابل جاسازی بدون تغییر آدرس |

## نکات پیاده‌سازی تولید

- یک فایل `seed.ts` بزرگ است چون پروتوتایپ است؛ در تولید هر دامنه سرویس خودش را دارد.
- صفحه‌های بزرگ (`Orders.tsx`، `Ops.tsx`، `Catalog.tsx`) با lazy route تقسیم شوند.
- `localStorage` فقط برای ترجیحات رابط بماند.
