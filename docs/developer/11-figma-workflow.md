# ۱۱ · فیگما: چرا دوباره کشیدن لازم نیست

## مشکل

تا امروز روال این بوده: کد پروتوتایپ ← دوباره کشیدن در فیگما ← دوباره کد زدن از روی فیگما. هر بار انتقال جزئیات از دست می‌رود (حالت‌ها، متن‌ها، فاصله‌ها، رفتار) و زمان دو برابر می‌شود.

## قاعدهٔ جدید

**کد این مخزن منبع حقیقت طراحی است.** فیگما برای نقد، کامنت و ایده‌پردازی است، نه برای بازسازی صفحه‌ها پیش از پیاده‌سازی.

| نیاز توسعه‌دهنده | از کجا بگیرد (به جای فیگما) |
|---|---|
| رنگ، قلم، فاصله، گوشه، سایه | `design-tokens.json` و `src/styles.css` |
| اندازهٔ دقیق هر جزء | پیش‌نمایش زنده + ابزار Inspect مرورگر (مثل Dev Mode فیگما ولی روی خودِ نسخهٔ نهایی) |
| کامپوننت‌ها و حالت‌ها | `/admin/design` در پیش‌نمایش و `src/shared/ui/` |
| چیدمان صفحه | تصویر صفحه در `docs/screens/` + خود صفحه در پیش‌نمایش |
| متن‌ها | خود کد (همهٔ متن‌ها فارسی و نهایی‌اند) |
| رفتار و جریان | پیش‌نمایش زنده؛ همهٔ دکمه‌ها کار می‌کنند |

اگر تیم فرانت‌اند همین React و Tailwind را ادامه دهد، **کامپوننت‌ها و صفحه‌ها مستقیم قابل استفاده‌اند** و فقط لایهٔ داده (`store.ts`) با API عوض می‌شود. این سریع‌ترین مسیر است.

## اگر باز هم فایل فیگما لازم است

بدون کشیدن دستی، در چند دقیقه:

1. **توکن‌ها**: افزونهٔ Tokens Studio for Figma ← Import ← فایل `docs/developer/design-tokens.json` ← ساخت Variables با دو حالت Light و Dark.
2. **صفحه‌ها**: افزونهٔ html.to.design ← آدرس پیش‌نمایش زندهٔ هر صفحه (مثلاً `https://behshad79.github.io/Ghanimat/#/admin/orders`) ← لایه‌های قابل ویرایش با همان قلم و رنگ. برای صفحه‌های نیازمند ورود، ابتدا در مرورگر وارد شوید و از نسخهٔ افزونهٔ مرورگر html.to.design استفاده کنید.
3. **تصاویر مرجع**: پوشهٔ `docs/screens/` را مستقیم در فیگما بکشید.
4. **قلم**: Peyda را از `src/fonts/peyda/` روی سیستم نصب کنید.

## از فیگما به کد (وقتی طراح چیزی تازه می‌کشد)

- از همان Variables وارد‌شده استفاده کند تا خروجی Dev Mode به نام توکن‌های کد اشاره کند (`brand-solid`، `text-t2`…).
- تغییر را روی پیش‌نمایش (artifact) بررسی و تأیید کنیم، بعد در مخزن منتشر شود؛ توسعه همیشه از نسخهٔ منتشرشده در GitHub کار می‌کند.
