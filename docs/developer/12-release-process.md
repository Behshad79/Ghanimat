# ۱۲ · روند انتشار و دریافت تغییرات

## چرخه

1. طراحی و تغییرات روی پیش‌نمایش داخلی بررسی و تأیید می‌شود. **تا تأیید نهایی چیزی در GitHub تغییر نمی‌کند.**
2. با تأیید، یک نسخهٔ تازه منتشر می‌شود:
   - کد در شاخهٔ `main`؛
   - یادداشت انتشار در `docs/releases/vX.Y.Z.md`؛
   - یک خط در `CHANGELOG.md`؛
   - برچسب git با نام `vX.Y.Z`؛
   - مستندات و تصاویر بازتولید می‌شوند؛
   - پیش‌نمایش GitHub Pages خودکار به‌روز می‌شود.
3. توسعه یادداشت انتشار را می‌خواند و بخش «کارهای توسعه» را اجرا می‌کند.

## یادداشت انتشار شامل چیست

قالب: [`../releases/_TEMPLATE.md`](../releases/_TEMPLATE.md)

- خلاصهٔ تغییر به زبان محصول؛
- صفحه‌ها و مسیرهای تازه یا تغییرکرده، با تصویر؛
- تغییر مدل داده (فیلد یا مجموعهٔ تازه، تغییر نوع)؛
- وضعیت‌ها و قانون‌های تازه؛
- عملیات (endpoint) تازه؛
- تغییر توکن یا کامپوننت؛
- **کارهای توسعه** به صورت فهرست قابل تیک؛
- فایل‌های تغییرکرده.

## دیدن تفاوت دقیق دو نسخه

```bash
git diff v1.0.0 v1.1.0 --stat
```

```bash
git diff v1.0.0 v1.1.0 -- src/shared/data
```

## نسخه‌گذاری

- `X` تغییر بزرگ در ساختار یا مدل داده؛
- `Y` قابلیت یا صفحهٔ تازه؛
- `Z` اصلاح و بهبود بدون تغییر قرارداد.
